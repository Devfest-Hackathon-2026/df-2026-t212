# Androidで試す方へ

今回は、After Hueを実際に使った感想と、操作中に困ったところを教えてください。コードを書いたり、開発環境を用意したりする必要はありません。

## インストールする

GitHubの招待を受け入れたら、[Android test build](https://github.com/pdHaku0/afterhue/actions/workflows/android.yml)の成功した手動実行を開きます。Artifactsにある `after-hue-android-ai-debug` をダウンロードし、ZIPを展開してください。中のAPKをAndroid端末にコピーして開くとインストールできます。端末からインストール元の許可を求められた場合は、今回使用したブラウザやファイルアプリについて確認してください。

このAPKにはAIの設定が入っているので、自分のAPIキーは不要です。名前に `local` が入ったAPKはキーなし版で、Askを使えません。どちらか分からなければ、所有者にダウンロード先を確認してください。

ダウンロードの有効期間は3日です。期限が切れた場合は、作り直しを依頼してください。取得済みのAPKやインストールしたアプリが3日で動かなくなるわけではありません。

AI入りのアプリは招待した方だけで試してください。所有者のAPIキーを組み込んでいるため、APKを公開したり再配布したりしないでください。

## 少し使ってみる

最初はテスト用の写真を数枚許可し、画面下の `+` から取り込んでください。1枚を開いて色を選び、Doneで保存して、もう一度開いてみます。Autoで現像を任せたり、Askに日本語で編集を頼んだりすることもできます。AIを使うと、写真の縮小版と編集依頼がOpenAIへ送られます。

使う順番を覚える必要はありません。次に何を押せばよいか分からなかった、予想と違う動きになった、仕上がりが気に入った、ということがあれば教えてください。Askの入力中に写真やSendが隠れる、保存した編集が消える、写真を開くとちらつく、といったことも確認したい点です。

処理中にDoneで編集画面を離れても、AIの処理は続きます。完了した結果はActivityから開けます。この流れが分かりやすかったかも知りたいです。

## 現在の制限

Android版は初期対応です。アプリ内カメラはまだ使えないので、端末のカメラで撮影してから `+` で取り込んでください。タップした物体の自動抽出も未対応ですが、Areaで手描きの範囲を指定することはできます。

GPSのない写真がMapに出ないのは想定どおりです。位置情報のある写真でも、写真の位置情報を読む権限がないと地図には出ません。

今回のAPKはテスト用のデバッグビルドです。速度について気づいた点も教えてください。ただし、iOS版との厳密な性能比較には使えません。

## 気づいたことを返す

GitHubのIssueでも、普段の連絡手段でも構いません。「端末とOS」「どの操作をしたか」「何が起きたか」が分かれば調査を始められます。原因の調査やコードの修正は必要ありません。可能なら画面のスクリーンショットや短い録画を添えてください。

セットアップをLLMに任せたい場合は、[README](../../README.md#セットアップをllmに任せる)の依頼文を使ってください。
