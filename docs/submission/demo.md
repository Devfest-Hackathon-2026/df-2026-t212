# デモの構成案

普段のカメラで撮った一枚が、色を残した表現に変わり、もう一度見返す対象になる流れを見せます。[課題設定](problem.md)に沿って、毎回手動で編集を始めなくても楽しめることと、気になった部分を本人が直せることをつなぎます。画面を次々に紹介するのではなく、同じ写真を追う構成です。以下は約2分10秒のデモ部分の案です。最新の提出ルールでは、現地会場は4分のピッチ（動画をGoogle Slidesに埋め込み、MP4本体も提出）、オンライン会場はデモを含めて5分以内のMP4です。登録会場に合わせ、課題・技術構成・選定理由を説明する時間を加えます。

## 0:00–0:15　いつもの写真を別の形で楽しむ

画面: 通常の写真と、主役の色を残した写真を比較する。

読み上げ案:
「普段はスマートフォンのカメラで撮って、編集はあまりしない。After Hueは、その写真を使い、色を残した別の表現で楽しむアプリです。自動取り込みと現像で、一枚ずつ編集を始めなくても仕上がりに出会えます。」

## 0:15–0:40　撮る・取り込む

画面: 写真ライブラリの写真が自動取り込みの結果に現れ、Activityから開く。アプリ内カメラは補助の経路として短く見せる。

読み上げ案:
「許可した写真から、新しい写真を見つけて現像します。自分で写真を選ぶことも、残す色を見ながらアプリのカメラで撮ることもできます。Autoでは、主役に合わせて残す色と範囲を調整します。」

カメラをSimulatorで再現した映像に置き換えません。待ち時間を省略するときは、映像内に「処理待ちを短縮」または倍率を表示します。

## 0:40–1:10　意図に合わせて仕上げる

画面: Autoの結果に対して、一か所だけ手動またはAskで修正する。元写真との比較を見せる。

読み上げ案:
「AIの結果が、自分の残したかったものと違うこともあります。そのときは色や範囲を直接変えるか、言葉で頼みます。AIも人も同じ編集設定を使うので、途中から自分で引き継げます。」

ここでは、実際にうまく再現できる依頼を一つに絞ります。AIが使っていないサービス名を画面や説明に追加しません。

## 1:10–1:35　色で見返す

画面: ギャラリーのパレットで絞り込み、地図上の色から写真を開く。

読み上げ案:
「残った色は、写真を見返すための手がかりになります。色から探したり、撮った場所から開いたりできます。一枚の編集が、そのまま自分の写真を眺める体験につながります。」

生成したデモ写真に日時・位置情報を付けたデータを使う場合は、「生成写真によるデモデータ」と表示します。実際にその日にその場所で撮った記録として紹介しません。

## 1:35–1:55　持ち出して残す

画面: Instantの印刷用画像にタイトル、場所、日付、色のバッジを追加する。Full photoへ切り替え、保存または印刷画面を開く。

読み上げ案:
「気に入った一枚には、短いタイトルや色を添えて残せます。余白を生かす形と、写真を全面に使う形を選べます。画像として共有することも、OSの印刷画面へ渡すこともできます。」

実物を印刷していない場合は、紙が出てくる演出を完成済み機能の証拠にしません。システムの印刷プレビューまでを見せます。

## 1:55–2:10　技術選択と次の検証

画面: 最終版の構成図を一枚表示する。

読み上げ案:
「AIには写真の解釈と編集の判断を任せ、画素の処理は端末内で行います。人が結果を調整できることを、この分担の基準にしました。次は、日々の写真を見返すきっかけとして使い続けられるかを検証します。」

Cloud Runで認証と利用量を確認してVertex AIへ渡し、AIが指定した編集を端末で描画する構成を示します。Firebaseは匿名認証、Firestoreは共有の利用回数管理です。Exploreの投稿・閲覧機能は今回のデモに含めません。

現在のVertex AI経路で、写真の選別、現像、追加の編集依頼、端末側の描画まで完走を確認しました。デモでは、この現在の経路で撮影した映像を使います。以前のAI経路で撮った動画を、現在のVertex AIの動作を示す証拠として使わないようにします。
