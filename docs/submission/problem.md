# 取り組む課題

普段の写真は、端末の標準カメラで撮ることが多い。開発者自身もそうでした。写真を別の表現で楽しもうとしても、そのたびに編集アプリを開き、写真を選び、加工する手順が必要になると、日常の撮影とは別の作業になります。

After Hueで考えたのは、すでに撮った写真を別の形で楽しむ方法です。残したい色を選び、ほかをモノクロにすると、元の写真の被写体や構図を残しながら、目を引く場所が変わります。新たに撮り直すことや、毎回一枚ずつ編集を始めることを前提にせず、いつもの写真ライブラリを使います。

自動取り込みと現像は、このためにあります。利用者が許可した写真を対象に、新しい写真を見つけて処理し、完了したまとまりへActivityから戻れるようにしました。使う写真を自分で選ぶことも、手動で編集することもできます。自動化は撮影の日常へ近づけるための選択肢であり、クラウドへ送ることには事前の同意が必要です。

色の表現は、一枚の仕上がりと一覧の見方をつなぎます。写真から取り出した質感のある色バッジを使うことで、写真そのものを小さく並べるだけでは見分けにくい場所にも、色の手がかりを置けます。地図では、写真が密集する場所でも色と位置から写真へ戻れる表示を目指しました。これにより探しやすくなったか、写真を見返す頻度が増えるかは、今後確かめる点です。

対象は、日常や旅行で写真を撮り、撮った後の写真にも楽しみを見つけたい人です。専門的な編集を最初から目的にする人だけに絞っていません。一方、AIの結果が好みと違う場合には、本人が色や範囲を調整できます。気に入った一枚は、タイトルや色バッジを添えた印刷用画像にもできます。

## 課題と実装の対応

| 日常で起きること | 対応する設計 | 確かめたいこと |
|---|---|---|
| 標準カメラで撮った後、別のアプリで編集を始める機会が少ない | 写真ライブラリからの自動取り込み、Auto、完了結果へ戻れるActivity | 撮影習慣を変えず、仕上がりに出会えるか |
| 自動処理が残す色と、本人が残したかった色が違う | 手動編集と共通の設定、Keep／Exclude、範囲指定、Ask、Undo | 好みと違う部分だけを直せるか |
| 写真が集まる場所を、地図上で一枚ずつ大きく表示できない | 写真由来の色バッジと、写真を開く地図表示 | 密集した場所でも、その写真らしさを手がかりに見返せるか |
| 気に入った仕上がりを、画面の外にも置きたい | 写真と文字・色バッジから作る印刷用画像 | 全体を見ながら、残したい形に整えられるか |

## 根拠と主張の範囲

この課題設定は、開発者の体験と開発中の具体的な操作から整理しています。社会全体に広く生じている問題だと示す調査や、利用頻度・編集時間への効果測定は行っていません。既存製品の不足を断定する比較もしていません。

設計の経緯と、実際の操作から変更した理由は[設計判断](design-decisions.md)にあります。写真を一般的な意味で「より良くする」ことよりも、本人の写真を、元の個性を残した別の表現で楽しめることを目指しています。Exploreは今回の提出対象に含めません。
