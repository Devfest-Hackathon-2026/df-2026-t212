## 構想と設計

- **写真の再発見と地図［構想・一部実装］** 写真がたまり目的のある見返しでは雑多になること、写真を色に圧縮すれば地図に配置しやすいことをユーザーが述べた。標準カメラの既存写真も opt-in で取り込み、加工に向いた写真を選び、写真の色を地図で時期や色から見る構想。期間窓を動かすアニメーションでは選ばれた実写真も表示するが、大量の重なりや単調さに配慮したかった。地域 SNS と結びつけず、公開もせず、表示・動画作成後の利用をユーザーに委ねるという区別を明示。動画の完成はこの調査では確認していない。（E 46, 51, 68, 98、11/7 14:26–15:29）
- **アプリと見た目［設計意図］** Flutter と Google Maps の当初案から開始。ユーザーは無彩色・ミニマルな基調、タイポグラフィと品格、写真の邪魔をしないこと、1画面に全機能を詰め込まないことを指定。名前は読みやすさと落ち着きを踏まえて `After Hue` に決めた。（E 124, 143–163、11/7 15:39–16:09）
- **色の指定とモーション［設計意図］** 色は原則として画像に触れて選び、HEX 等は高度な選択肢にとどめる。アニメーションを無くすのでなく、ちらつきを抑え体験を改善する自然な動きや触覚を重視。標準カメラ経由も自前カメラも使い、自前では撮影前に色選択と加工プレビューを行う意図。（E 302、11/7 16:49）
- **二値ではない色の残し方［実装・試作確認］** Accent の観察から、選択色だけを急に残すと不自然なため、近い色ほど残し、距離に応じて滑らかにモノクロに近づけるよう要求。試作の Python 現像器は Width / Softness とぼかした領域指定、低彩度部分への対策を使用。3種類の写真で各3ラウンド試し、被写体と背景が似た色になる例では色だけで分けられず、領域指定も要ったと報告。ユーザーがピアノのピンクやクレープの生地まで灰色なのは不自然と指摘し、2色を残すよう再試作した。ピアノの脚付近は拡大目視未確認、被写体と同色の物が重なる場合は色と粗い領域だけでは除外しきれないと留保。（E 660, 721, 806, 1110, 1115, 1254, 1268、11/7 17:01–18:41）
- **生成画面を参考に検討［試作・採否を区別］** 画像生成で8画面を作り、写真の質感を持った色見本、地図の写真カード等を検討。生成に使われたモデル名は確認できなかった、と当時明記している。生成物の全要素が採用されたわけではない。（E 660, 721, 801、11/7 17:01–17:07）

## 処理・人と AI の協働

- **決定的レンダリングとレシピ［実装報告］** 初期試作は写真そのものを生成せず、色空間上の画素に重みをかけ、領域やトーンのパラメータを JSON レシピで表す方式。Dart と Python のレンダラーは、当時の報告で平均差が画素値 255 段階中約1だった。Claude が写真を見て Gemini の役を代行した実験であり、これ自体を Gemini の実行実績と扱わない。（E 806, 1110, 1404、11/7 18:30–18:47）
- **手動インポートは編集へ、AI は割り込み可能に［実装・Simulator 確認］** 自分でインポートしたのに自動 AI 処理が始まることへの違和感から、手動インポートは直接編集画面に入り、Auto は必要なときに実行する方針へ。AI 処理中に人が介入すると、途中設定を引き継いで止められる仕組み。ユーザーの操作が反映されない問題は、レンダリング負荷への対応に加え、別スレッドへ画面状態を送ろうとして失敗する真因を修正。Simulator で手動インポート、色取得、編集画面の Auto 中の引き継ぎを確認した一方、ギャラリーからの割り込みと Tone は当時未確認。（E 3285, 3636, 4264、11/7 19:49–20:07）
- **自動処理の対象とコスト［当時の実装・一部未検証］** 取り込んだ写真を無差別に AI に渡すことを懸念し、端末側の無彩色判定や連写代表の選別、モデルでの適性判定を経て現像する仕組みを導入したと報告。後に、20秒・50m以内を同シーンにまとめ代表を処理し、構図がずれる可能性から5秒以上離れた写真には領域をコピーしない、という扱いを報告。過去写真を30枚ずつ処理するボタン、iOS のスクリーンショットアルバムを使った除外も追加。ただし当時の報告ではシーンのまとまりとスクショ除外は動作未確認。Apple モデルの画像入力可否についての初期想定をそのまま現在の能力として主張しない。（E 4586, 5262, 5633, 6063、11/7 20:37–21:05）
- **雰囲気とビネット［実装報告］** モノクロ部分が無彩色すぎるという指摘を受け、背景の元の色味を薄く残す Mood を試した。ビネットが濃さだけで範囲固定だった問題には、Core Image の挙動を測って強さと Radius を分離。写真アプリ内部が同じ API を使っているかは確認できなかったと明記。スウォッチやハートには現像画像内の対象色が密集する小領域を使い、色だけでなく写真の質感を表示した。（E 6126, 6537–6565, 7151, 7689、11/7 21:06–21:25）
- **マスク外の色選択と AI 修正［実装・Simulator 確認］** マスク範囲外をタップすると色を選んでも変化せず困る実体験から、地点と色を AI に伝えて範囲を修正する導線を提案。提案時点では未実装だったが、後に Ask の文章入力と候補、写真上の番号付き Keep / Remove の印、範囲外での修正提案、進捗・結果表示、AI の変更をまとめて戻す Undo を実装したと報告。長押しはルーペと競合するため、印は Ask 中のタップ方式に変更。Simulator の自販機写真では、本体を残しボトル窓を白黒にする依頼と、範囲外で取ったボトルの色を戻す操作を確認。ただし AI は「その1本」と解釈し、同色の全ボトルを戻すには言葉の補足が必要だった。端末にはインストールしたが当時実機での操作は未確認。（E 7694, 7747, 8998, 9082、11/7 21:25–21:43）
