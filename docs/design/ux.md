# After Hue — UX 設計

v0.2 · 2026-11-08 · 上野
状態：設計中。§11 の仮説はプロトタイプで検証して決める。

---

## 0. After Hue とは

写真の主役の色だけを残し、それ以外をモノクロにする写真アプリ。
主役の判定から加工の調整までを AI エージェントが行うので、ユーザーは色を選ばなくていい。
残った色は撮影した時間と場所に紐づいて蓄積され、ギャラリーと地図で見返せる。

撮影は After Hue のカメラでも、いつもの標準カメラでもいい。標準カメラで撮った写真は、許可すれば自動で取り込まれる。

## 1. なぜ作るか

### 1.1 いまの不満
- **セレクティブカラーのアプリは、編集のための道具に留まっている。** 1枚ずつ開き、色を選び、調整し、書き出す。作品づくりには良いが、毎日の写真には重すぎる。結果として、特別な1枚にしか使われない。
- **写真ライブラリは溜まる一方で、見返されない。** 写真アプリは1枚単位でしか見られず、量が増えるほど自分の日々を見渡せなくなる。アルバムや自動分類はあるが、それは「探す」ための仕組みで、「眺める」ための仕組みではない。

### 1.2 After Hue の答え
- 色の選択と調整を AI が担うことで、セレクティブカラーを**毎日の写真に使える軽さ**にする。
- 1枚の写真を「主役の色」という小さな単位に圧縮することで、**数千枚を時間と場所の上で一度に見渡せる**ようにする。写真のサムネイルは地図に並べると読めなくなるが、色なら並べられる。

### 1.3 既存のものとの違い

| | 何をするか | After Hue との違い |
|---|---|---|
| Accent などのセレクティブカラーアプリ | 1枚を手作業で編集する | After Hue は AI が全部やり、結果が蓄積される |
| Hueprint・Tinc・Palette Collect などのパレット抽出アプリ | 写真から配色を取り出し、デザイン素材として保存する | 目的が素材集め。写真そのものは変わらず、時間と場所の軸もない |
| Google フォト・Apple 写真 | 写真を整理し、探しやすくする | 写真の量はそのまま。色という切り口で俯瞰する手段はない |

### 1.4 AI と人間の役割
作業は AI がすべて行う。ただし、どの色を残すかの最終判断は、いつでも人間がタップひとつで上書きできる。
**任せられるけど、手放さない。** これがプロダクト全体の姿勢。

## 2. 体験の全体像

```
  撮る                       現像する                 眺める              残す
 ─────────────────────────────────────────────────────────────────────────────
  After Hue のカメラ ──┐
  （その場で色を見ながら）│                          Photos（時間で）    共有シート
                      ├─→ エージェントが主役を ─→    Map（場所と時間で）→ ・保存
  標準カメラ ──────────┤   判定し、色を残す           Search / Filter      ・SNS に投稿
  （自動取り込み）       │                                                  ・地図の再生を動画に
                      │
  手動で選ぶ ──────────┘
```

利用頻度で並べると：
1. **ふと開く**（毎日〜週数回、数十秒）：新しく現像された写真を眺めて閉じる。**操作ゼロで満足できること**が最優先。
2. **撮る**（気が向いたとき）：After Hue のカメラで、色を見ながら撮る。
3. **見返す・探す**（月数回、数分）：ある色、ある時期、ある場所の写真を眺める。地図で再生する。
4. **整える・残す**（たまに）：気に入った写真を微調整して共有する。地図の再生を動画にする。

## 3. 設計原則

判断に迷ったらここに戻る。上ほど優先。

### 3.1 色はユーザーのものだけ
UI は無彩色で作る。画面に色があるとしたら、それはユーザーの写真から残された色。
アプリが主役にならないための最も強い制約で、同時に、ユーザーの色を最も美しく見せる条件でもある。

### 3.2 何もしなくても申し分ない
ユーザーの操作は「任意」であって「必要」ではない。
取り込み・選別・主役の判定・調整まで、エージェントが申し分ない品質で終わらせる。直したい人だけが直す。

### 3.3 入力させない
色は**写真をタップして選ぶ**。名前を打たせない、数値を打たせない。
HEX や色相の数値は、それを求める人のための詳細モードに置く。
文字を打つのは検索だけで、それも Palette のタップで代わりに探せるようにする。

### 3.4 1画面1仕事
各画面が担う仕事は1つ。2つ目の仕事が要るなら、画面を分けるかシートに逃がす。

### 3.5 動きで説明し、触感で応える
アニメーションを削ると、画面は切り替わるたびにちらつき、かえってうるさくなる。
After Hue の動きは飾りではなく、**どこから来て、どこへ行ったか**を伝えるためのもの。
退屈な操作が心地よくなるよう、モーションとハプティクスを一緒に設計する（§8）。

## 4. 概念モデル

```
Scene ─ 同じ被写体を、同じ日に、同じ場所で撮った写真のまとまり
 └ Photo ─ 元写真への参照・撮影日時・位置
     └ Edit ─ 加工の設定（非破壊。元写真は書き換えない）
         └ Hue ─ 残された色（1〜3 色）
Palette ─ ユーザーが集めた Hue を、似た色ごとにまとめたもの
```

### 4.1 Scene（シーン）を置く理由
同じものを何枚も撮るのは、写真を撮る人の普通の振る舞い。これを1枚ずつ扱うと、次の3つの問題が同時に起きる。

1. **編集**：同じ加工を何枚にも繰り返すことになる。
2. **地図**：同じ場所・同じ時間に同じ色が積み重なり、色の偏りとして見えてしまう。
3. **費用**：ほぼ同じ写真を何度も AI に送ることになる。

Scene はこの3つをまとめて解く。
- エージェントは Scene の代表1枚だけを判定・調整し、その Edit を残りの写真に適用する。
- 地図では Scene を1つのマーカーとして描く（枚数を小さく添える）。
- ギャラリーでは Scene を重なったカードとして見せ、開くと中の写真を横に送れる。

Scene の判定は端末内で行う。撮影時刻の近さ、位置の近さ、画像の類似度の3つを満たすものをまとめる。
誤ってまとまったときは、Scene を開いて「Split」で分けられる。

### 4.2 Palette（パレット）
集めた Hue を似た色ごとにまとめたもの。ユーザーが実際に集めた色だけでできた、その人だけの色見本。
絞り込み・並べ替え・検索の入口になる（§6.3）。

## 5. ナビゲーション

### 5.1 構造
```
Bottom bar：  Photos ・ Map            ◉ Camera
                │        │                │
                │        │                └ カメラ（全画面）
                │        └ 地図 → 再生 → 動画の書き出し
                └ ギャラリー → 写真詳細 → 編集
                                    └ 書き出し → 共有シート
共通：Search / Filter（Photos と Map で状態を共有）
その他：Settings（Photos の右上から）
```

### 5.2 ボトムバー
- 画面下に浮かぶガラス質のバー。左に `Photos` `Map`、右に独立した丸いカメラボタン。
- ラベルは英語の文字だけで始める。アイコンを付ける案も並行して試し、比べて決める（§11）。アイコンを使う場合は、公開アイコンセットではなくフルスクラッチで作り、ブランドの造形言語にする。
- カメラボタンだけを分けて丸くするのは、カメラが「場所」ではなく「行為」だから。押すと全画面のカメラが下から立ち上がる。
- スクロール中はバーを少し沈め、止まると戻す。

### 5.3 Photos と Map は同じデータの2つの見え方
Photos は時間で、Map は場所と時間で、同じ写真の集まりを見る。
だから Search と Filter の状態は2つの間で共有する。Map で「この秋の赤」に絞ったまま Photos に移れば、その赤の写真が並ぶ。

## 6. 画面

### 6.1 オンボーディング

**説明は普通の文章で書く。** キャッチコピーで雰囲気を作るより、何が起きるかを正確に伝える方が誠実で、伝わる。
言葉を補うのは動き。各画面で、実際の写真がモノクロになり、主役の色だけが戻る様子を見せる。

| # | 画面の文章 | 操作 |
|---|---|---|
| 1 | After Hue finds the subject of each photo and keeps only its color. Everything else turns black and white. | `Continue` |
| 2 | To do this automatically, After Hue needs access to your photos. You can also choose specific photos instead. | `Allow Access` / `Choose Photos` |
| 3 | Photos are resized and sent to Google Gemini for analysis. Location and time stay on this device. | `Start` |

- 遡る範囲は既定で直近 12 か月。3 画面目に小さく `Last 12 months · Change` と出す。画面を1枚増やして選ばせることはしない。
- 処理は常に新しい写真から進むので、範囲を広げても最初の1枚が出るまでの時間は変わらない。
- **アカウント登録・課金・通知の許可はここで求めない。** 必要になった時点で求める。

### 6.2 現像中（初回）
- 待たせない。**最初の1枚が仕上がった瞬間に、ギャラリーへ移る。**
- 残りは裏で進み、ギャラリー上端に1行だけ進捗を出す（`Developing 42 of 380`）。終われば静かに消える。
- 仕上がった写真は、モノクロで現れてから主役の色が戻る演出とともに、上から差し込まれる。待ち時間そのものを見どころにする。

### 6.3 Photos（ギャラリー）

ギャラリーは「見返す」「探す」というさまざまな要求に応える場所であり、同時に、**色で写真を扱うというプロダクトの思想が最も見える場所**でもある。

**基本の表示**
- 3 列のグリッド。ピンチで 5 列 / 1 列。
- 正方形のトリミングは、主役の位置を中心に行う。中央で切ると、残した色がサムネイルから外れることがある。
- Scene は重なったカードとして表示し、右下に枚数。
- 新しく現像された写真には、一度見るまで小さな点を付ける（無彩色）。

**色ならではの見方**
| 機能 | 内容 |
|---|---|
| **Palette で絞り込む** | 上部に、ユーザーが集めた色のパレットを横一列に並べる。タップでその色の写真だけに絞る。複数選択可。汎用の色相環ではなく、自分が集めた色から選べることが大事 |
| **色で並べる** | 並び順を `Time` と `Hue` で切り替える。`Hue` にすると、グリッドが色相順のグラデーションになる。並べ替えるだけで、自分の写真の色の偏りが一目で分かる |
| **月ごとの色** | 時間順のとき、月の見出しの横に、その月に集めた色を小さく並べる |
| **似た色を探す** | 写真詳細で残った色をタップすると、似た色の写真が並ぶ |

**検索**
- 上部の `Search` から、被写体・場所・時期で探す（`umbrella`、`Kyoto`、`October`）。
- エージェントが判定時に付けた被写体の記述と、撮影地・日時を索引にする。将来は画像の埋め込みで、言葉にしにくい雰囲気でも探せるようにする。
- 検索語と Palette の絞り込みは組み合わせられる（`umbrella` × 赤）。

**複数選択**
- 長押しで選択モードに入り、なぞって範囲選択。
- 選択中にできること：`Paste Edit`・`Share`・`Remove`。

### 6.4 写真詳細
**仕事：1枚を見る。比べる。**

- 写真を全面に表示し、UI は最小限にする。
- **押し続けると元の写真**に戻り、離すと After Hue の写真に戻る。比較はこれだけで行う。見えない操作なので、初めて詳細を開いたときだけ、一度ヒントを出す。
- 写真の下に、残った色の色見本（1〜3 色）と、撮影日時・場所（等幅、小さく）。
- 下部の操作：`Edit` `Favorite` `Share` `More`
- `More` の中：`Duplicate`・`Copy Edit`・`Paste Edit`・`Why this color?`（エージェントの判断理由）・`Remove from After Hue`
- **編集の複製**：`Copy Edit` で加工設定をコピーし、ギャラリーで複数選択して `Paste Edit`。iOS の写真アプリと同じ流れなので、学び直しがいらない。
- **写真の複製**：`Duplicate` で同じ写真の別バージョンを作る。残す色を変えた2枚を並べたいときに使う。
- Scene の中では、左右スワイプで同じ Scene の写真へ、Scene の端を越えると前後の写真へ移る。
- 下スワイプで閉じ、ギャラリーの元の位置へ縮んで戻る。

### 6.5 編集
**仕事：エージェントの仕事を、人間が上書きする。**
人間が使う道具は、エージェントが使う道具とまったく同じ（§7）。

**色の選び方**
- **写真をタップ**して、その位置の色を残す色に加える。
- **長押しするとルーペ**が出て、指の下を拡大して見ながら正確に選べる。指を離した位置で確定する。
- 写真から抽出した候補の色を、パネルに色見本として並べる。写真の中から探さなくても、タップで選べる。
- 残す色は最大 3 色。色見本の長押しで外す。

**色の残り方：0 か 1 ではなく、なだらかに**
色を「残す / 消す」の二択で処理すると、境目で色がぷつりと切れて、ひどく不自然になる。
After Hue では、選んだ色に近い色ほど彩度を多く残し、遠い色ほど連続的にモノクロへ近づける。
- `Width`：どこまでの色を「近い」とみなすか
- `Softness`：近い色から遠い色へ、どれだけなだらかに彩度を落とすか
この2つが加工の中心で、エージェントが最もよく調整する値でもある。

**範囲を限る（Area）**
同じ色が写真の別の場所にもあるとき、残す場所を限りたくなる（看板の橙は残したいが、奥の立て看板の橙は消したい、など）。

- 既存のアプリは、円・四角・投げ縄・ブラシで形を描き、その内側だけ色を残す。しかし**形の縁がくっきりしているので、境界がそのまま写真に出てしまう**。同じ色の面を形の線が横切ると、そこで色が切れ、加工した跡が見える。
- After Hue の範囲は、**縁のぼかしの強さ（`Edge`）を指定できる**ようにする。縁を十分にぼかせば、範囲の内と外の切り替わりは、色のなだらかな残り方と同じ質感になり、線として見えなくなる。範囲の形は円と自由な塗りから始める。
- **オプション：色に合わせて広げる（`Snap to color`）**。範囲を描いたあと、範囲の中で残っている色と似た色の領域を判定し、そこまで範囲を少し広げる。同じ色の面の途中で範囲が終わってしまうのを防げる。判定を誤ると思わぬ所まで広がるので、既定はオフにして、使うかどうかを選べるようにする。
- エージェントも同じ道具を使う。主役の位置が分かっているので、主役を囲む範囲を自動で置ける。

**パネル**
- 下部のツール切り替え：`Accent`（残す色）・`Range`（`Width` と `Softness`）・`Area`（残す場所と `Edge`）・`Mono`（モノクロ部分のトーン）
- 開くパネルは一度に1つだけ。パネルは畳める。
- **パネル右上に詳細モードのトグル**。オンにすると、色見本に HEX が、スライダーに色相の範囲と数値が出る。直接入力もできる。既定はオフ。
- `Auto` でエージェントの提案に戻す。`Undo` は上部に。

### 6.6 Camera
**仕事：撮る前に、仕上がりを見ながら撮る。**

- ファインダーには、残す色を適用したプレビューがリアルタイムでかかる。
- 起動直後は、画面内で最も主役らしい色を端末内で推定して自動で選ぶ。ファインダーをタップすると、その位置の色に切り替わる。長押しでルーペ。
- シャッターで撮った写真は、**元の写真を端末の写真ライブラリに保存**し、After Hue は加工設定だけを持つ。あとから何度でも残す色を変えられる。
- After Hue で撮った写真は自分で覚えておき、自動取り込みで二重に取り込まない。
- 撮影後、エージェントが改めて判定する。ユーザーがファインダーで選んだ色は尊重し、上書きしない。
- 標準カメラで撮った写真も、取り込まれれば同じように扱う。どちらで撮っても結果は同じ場所に集まる。

### 6.7 Map
**仕事：色を、場所と時間で眺める。**

**地図のキャンバス**
- 明るいキャンバスにする。ダークの地図はほぼ青みを帯びていて、ユーザーの色とぶつかる。明るい地図の方が色数が少なく、目にも受け入れやすく、紙のキャンバスに色を置いていく感覚にも合う。
- 完全なグレースケールだと、道や水域が見分けにくくなる懸念がある。明度の階調で地形を描き分ける案、ほぼ無彩色の紙色の案、線だけで描く案を比較して決める（§11）。

**マーカー**
- 1 Scene = 1 マーカー。複数の色を持つ写真は、1つのマーカーを色の数で分割して描く。1枚が3つの点になると、色の多い写真だけが重みを持ってしまうため。
- 形は、色を入れた小さな角丸の吹き出しを第一候補に、複数の形を比較して決める（§11）。
- ズームアウトでまとまるときは**色を混ぜない**。混ぜた色は濁り、誰の色でもなくなる。含まれる色ごとに弧を分けたリングで描く。
- マーカーをタップすると、近くに小さなカード（サムネイル・日時）。カードをタップで写真詳細へ。

**期間ウィンドウと再生**
- 画面下部に時間軸と期間ウィンドウ。両端で長さを、中央のドラッグで位置を変える。
- ウィンドウの外のマーカーは消さずに、ごく薄い点として残す。どこに行ったかという文脈を失わないため。
- `Play` で、ウィンドウが一定の長さのまま時間を進む。マーカーは時間に合わせて現れ、ウィンドウを出ると薄い点へ縮む。
- 再生中は他の UI を下げ、地図と時間軸だけにする。

**お気に入りの写真を浮かべる**
- 再生中、お気に入りの写真（なければエージェントが選んだもの）を、地図のピンのように場所へ刺した小さなガラスの吹き出しで浮かべる。
- **写真は時間に同期させる。** 写真の撮影時刻がウィンドウの中にある間だけ表示し、出たら消える。キューで順番待ちさせない（待たせると時間とずれて意味がなくなる）。
- 縦画面では同時に4枚程度まで。大きさ・位置・どれを出すかは、空いている場所・重なり・優先度から動的に決める。
- 同じ場所の写真が続くときは、1枚にまとめる。

**動画の書き出し**
- `Play` の状態から `Export Video`。比率（9:16・1:1・16:9）、写真の表示の有無、日付の表示の有無を選び、書き出して共有シートへ。

### 6.8 書き出しと共有
- **共有シートを経由する。** 保存も SNS への投稿も、iOS の共有シートから行う。そのまま X や Instagram に投稿でき、書き出したあとは完全にユーザーの自由。
- 書き出しのプレビューで、フレームの有無・残した色の色見本の有無・比率を選べる。
- フレームには、控えめに After Hue のワードマークを入れられる（既定はオフ）。投稿を見た人がアプリを知る入口になるが、ユーザーの写真を広告にはしない。

### 6.9 Settings とアカウント
- 自動取り込み（オン / オフ）・遡る範囲・Wi-Fi のときだけ処理する・スクリーンショットを除外する。
- **アカウント**：将来は課金と合わせて提供する。Gemini の利用には費用がかかるため、サブスクリプションを想定している。いまは `Coming soon` として、提供予定の内容を3つだけ示す。
  - Sync across your devices
  - Cloud backup of your photos and edits
  - More AI edits each month

## 7. エージェント

### 7.1 流れ
```
1. 候補（端末内）   スクリーンショット・ほぼ無彩色・色が薄く全体にかかっているだけの写真を除外する。外には何も送らない
2. Scene（端末内）  3 秒以内の連写は最新の1枚だけを送り、他は手動に回す（理由を表示）
3. 判定（端末内 LLM） Apple の端末内モデル（Foundation Models, iOS 27, 画像入力）が主役と、残す価値があるかを決める
                   使えない端末では軽量クラウドモデル（gpt-6-luna）。判定に失敗したら通す
                   落ちた写真は白黒のまま残り、Edit に理由が出る。人が Auto を押せば判定なしで現像する
4. 作業（Gemini）   ツールを呼んで加工設定を決める。人間の編集画面と同じ道具
                   add_color / remove_color / set_width / set_softness / set_area / set_mono_tone
5. 描画（端末内）   決定的な処理で低解像度のプレビューを描く
6. 自己評価         Gemini がプレビューを見て、主役が立っているか、境界が汚くないかを判定する
                   不十分なら 4 に戻る（最大 3 回）
7. 適用            代表の Edit を Scene 内の他の写真に適用する
```

### 7.2 判断の理由
- **加工は生成ではなく、決定的な処理で行う。** 画像生成モデルで編集するとピクセルが作り変わり、写真が記録として信用できなくなる。AI には判断と調整だけをさせる。
- **選別は安いモデルに任せ、作業は賢いモデルに任せる。** 写真を全部クラウドの賢いモデルに送ると費用も通信も重い。判定は「主役があって、その色が立つか」の二択に絞り、端末内モデルで済ませる（無料・オフライン・写真が外に出ない）。迷う写真は通す側に倒す。落とした写真も消さず、人がいつでも現像できる。
- **自動で現像する枚数に上限を置く。** 初回は新しい 20 枚まで、その後は新しく撮った写真だけ、1 日 30 枚まで。
- **すでに一部だけ鮮やかな写真も落とさない。** 撮った人が、まさにその色に気づいて撮った可能性が高い。
- 元写真は書き換えない。After Hue は Edit だけを持ち、表示時に適用する。
- Gemini に送るのは縮小した画像だけ。位置と日時は送らない。

## 8. モーションとハプティクス

### 8.1 モーションの原則
1. **連続性**：画面が変わっても、物はつながっている。ギャラリーのサムネイルは、そのまま写真詳細に拡大する。閉じると元の位置へ縮んで戻る。
2. **物理**：動きはばね（スプリング）で表す。一定時間のイージングではなく、指の速さを引き継いで動く。
3. **割り込める**：動いている途中でも、触ればその位置から操作を引き継げる。アニメーションの終わりを待たせない。
4. **意味のある動きだけ**：動きは「どこから来て、どこへ行ったか」を伝えるために使う。意味のない装飾の動きは入れない。

### 8.2 署名的な動き：色が戻る
写真はモノクロで現れ、主役の色だけがゆっくりと戻る。アプリ名そのものを表す動き。
- 新しく現像された写真が初めて表示されるとき
- オンボーディング
- 編集で残す色を加えたとき（短縮版）
- 地図でマーカーが現れるとき（極短縮版）

### 8.3 地図のマーカー
- 現れるとき：小さく沈んだ位置からばねで立ち上がる。
- 去るとき：薄い点へ縮み、その場に残る。
- 再生中に同時に多数が現れるときは、わずかに時間差をつけて、まとまりとして波のように見せる。
- 複数の動きの案を比較して決める（§11）。

### 8.4 ハプティクス
使う場面を絞り、触ったことへの返事としてだけ使う。勝手に震わせない。

| 場面 | 触感 |
|---|---|
| 写真をタップして色を選んだ | 軽いクリック |
| ルーペで選んでいる間、色の境界をまたいだ | ごく軽い刻み |
| スライダーが既定値を通過した | 軽い刻み（戻しやすくするため） |
| シャッター | しっかりとした一打 |
| 地図の時間軸を動かして、月の境目をまたいだ | ごく軽い刻み |
| お気に入りに追加 | 軽い一打 |

## 9. ビジュアル

- **言語**：UI は英語のみ。平易な英語は短く、ラベルが整い、世界のどこでもそのまま使える。
- **色**：UI は無彩色。背景は純白を避けた明るいグレー。純黒も使わない。
- **書体**
  - UI：iOS では Helvetica Neue をシステムフォントとして指定して使う（ライセンスの都合で同梱はできない）。Android と Web では Inter で代替する。
  - 撮影日時・場所・数値：等幅（JetBrains Mono などを同梱）。記録としての静けさを出す。
- **形**：角丸は控えめ。影はほぼ使わず、境界は細い線か面の明度差で表す。浮かぶ部品（ボトムバー・地図上の写真）だけをガラス質にする。
- **アイコン**：フルスクラッチで作る場合、細い線を基本に、選択状態だけ塗る。

## 11. 検証する仮説

文章だけでは決められないものは、実物を作って比べてから決める。
比較用の資料は `docs/design/explorations/` に置く。

| 仮説 | 比べるもの | 何で決めるか |
|---|---|---|
| 地図のキャンバス | 明度の階調だけのグレー / ほぼ無彩色の紙色 / 線だけ | ユーザーの色が一番きれいに見え、かつ道や水域が読めるもの |
| マーカーの形 | 角丸の色見本 / 角丸の吹き出し / ピン / ガラス / 分割 | 密集しても読めるか、色が濁らないか、位置が正確に分かるか |
| マーカーの出入りの動き | ばねで立ち上がる / 上から落ちて止まる / モノクロから色が満ちる | 再生中に心地よく、うるさくないもの |
| ボトムバー | 文字だけ / アイコンと文字 | 迷わず押せるか、画面の静けさを壊さないか |
| 時間軸の見せ方 | ギャラリーと地図で共通の「色の帯」/ それぞれ専用の時間軸 | 共通にすると一貫性が出るが、役割の違う部品を同じ見た目にすると混乱する恐れもある。実物で判断する |

## 12. 採らなかった案

| 案 | 理由 |
|---|---|
| 色を言葉で呼ぶ（「傘の赤」など） | 色を区別する手段として言葉は不正確で、入力も求めることになる。色は色見本で見せ、タップで選ぶ |
| 新着をレビューする画面（採用 / 不採用をスワイプ） | 人間の操作を前提にしてしまう。§3.2 に反する |
| ダークの地図 | 青みがかっていて、ユーザーの色とぶつかる |
| 地図にすべての写真をサムネイルで置く | 重なって読めない。写真はお気に入りだけを、再生中だけ、時間に同期して出す |
| お気に入りの写真をキューで順番に出す | 待たせると撮影時刻とずれて、時間軸の意味がなくなる |
| 画像生成モデルで直接加工する | 写真の記録性が失われる |
| 色を 0 か 1 で残す | 境目で色が切れて不自然になる。近い色ほど多く残し、遠い色ほどなだらかにモノクロへ近づける（§6.5） |
| 縁のくっきりした範囲指定 | 範囲の線が同じ色の面を横切ると、境界が写真に出る。縁のぼかしを指定できるようにする（§6.5） |
| 公開・共有のタイムライン | 個人のための道具に徹する。共有は OS の共有シートに任せる |
| 日本語 UI | 英語のみにすることで、ラベルが短く整い、世界にそのまま出せる |
